# Screenshot-Driven UI Redesign

## 目标
把截图作为现状证据，而不是照抄模板。根据用户目标（例如清晰度、效率、品牌表达、信任、转化、留存、上手难度或无障碍）重构页面；“购买”只是可能目标之一，不能定义整个专家的默认方向。

## 第一步：证据边界
先列出：
- 截图中实际可见的页面类型、信息层级、布局、组件、文字、颜色、操作入口和状态；
- 用户明确给出的业务目标、平台、受众、品牌和技术约束；
- 不能从静态截图确认的行为：真实数据、用户偏好、转化率、隐藏交互、加载/失败/空状态、移动端与键盘行为；
- 需要通过 AskUserQuestion、用户材料、网站研究或 Playwright QA 才能确认的事项。

## 第二步：灵感来源决定
若用户没有说明灵感网站或是否可用外部参考，主动使用 AskUserQuestion 一次，询问：
- 用户提供链接/网站；
- 使用内置公开参考来源；
- 允许扩展公开网页研究；
- 不使用外部参考。

用户给自由描述、URL、截图或文件时不要把它们塞进选择卡；继续正常对话。用户已经选择或提供来源时不得重复询问。

## 第三步：原创方向
在研究和诊断后给出 2–3 个真正不同的方向。每个方向必须包含：
- 名称与解决的用户任务；
- 信息架构和视觉层级变化；
- Token 倾向、布局节奏、组件状态和响应式策略；
- 适配理由、风险、不可用场景；
- 与来源之间的抽象关系，而非复刻关系。

不要为了“更好看”牺牲核心任务、可读性、无障碍、品牌一致性或真实性。不要生成误导性促销、虚假稀缺、隐藏费用、假安全标识或其他暗黑模式。

## 第四步：实现和验证
用户选择方向或上下文足够时，先输出可实施规范，再在有授权目录和真实 Write/Edit 时生成 HTML。若 Bash/Playwright 真实可用，遵循 `playwright-visual-qc` 做多视口检查；未执行时明确写为未验证。
