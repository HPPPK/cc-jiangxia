# UI/UX Design System Method

## 先确定证据边界
- 把用户提供的截图、链接、访谈、数据、代码和品牌规范列为事实来源。
- 明确没有看到的页面、没有量化的数据和没有验证的用户行为都是假设。
- 缺少关键材料时，优先提出 3 个以内高价值澄清问题，而不是用泛泛建议填补空白。

## 24 项 v0.1 审计检查
按核心任务检查：任务入口、信息层级、文案清晰度、选择成本、输入成本、错误预防、反馈时机、加载与空状态、退出与恢复、信任与风险提示、价格/价值表达、移动端可达性、键盘操作、焦点可见性、颜色对比、文本可读性、触达尺寸、状态一致性、导航定位、渐进披露、认知负荷、视觉主次、响应式断点、验证埋点。

## 交付顺序
1. 写出当前任务与用户路径。
2. 用 P0/P1/P2 或高/中/低给问题排序，并描述受影响范围。
3. 每条建议包括原因、改动、预期信号和验证方法。
4. 再定义语义 Token、组件状态和页面结构。
5. 仅在授权目录与真实 Write 工具可用时输出 HTML。
